# RimDelegation · 战斗计算验证器（CombatLab）

游戏**外**的桌面程序，用来摆敌我编队、跑抽象战斗、看预告与战报。
它不碰 RimWorld，也不进 `Source/`，所以对 mod 本体零影响。

## 运行

双击 `CombatLab.cmd`，或：

```powershell
cd RimDelegation\CombatLab
dotnet run                      # 开发模式直接跑
```

已发布的独立产物在 `dist\`（约 250 KB，依赖 .NET 10 桌面运行时）：

```
dist\RimDelegation.CombatLab.exe
```

命令行模式（便于脚本化 / 回归）：

```powershell
RimDelegation.CombatLab.exe --selftest                 # 无头跑 41 项断言，退出码 = 是否有失败
RimDelegation.CombatLab.exe --smoke                    # 无头跑全部预设 + 与控制台**进程内**交叉验证
RimDelegation.CombatLab.exe --sweep cover              # 扫描「掩体通过率」
RimDelegation.CombatLab.exe --sweep noadv 海盗哨所      # 扫描「无地形优势的射程系数」
RimDelegation.CombatLab.exe --sweep start 海盗哨所      # 扫描「初始交战距离」
RimDelegation.CombatLab.exe --sweep standoff 海盗哨所   # 扫描「纵深上限」
RimDelegation.CombatLab.exe --sweep enemyfactor 猎杀    # 扫描「敌方输出修正」（参数可给预设名前缀）
RimDelegation.CombatLab.exe --render out.png           # 离屏渲染界面（同时产出 out-log.png 战报页）
```

`--smoke` 会把每个共享预设与控制台 `Scenarios` 里的同名场景**在同一个进程里各跑一次**，
比对胜率（差值 > 8 个百分点即失败）—— 两个工程链接同一批源文件，所以这是对
"共用同一核心"的实测，而不是靠"引用了同一个文件"的推论。当前四个预设差值均为 **0%**。

四个旋钮的分工（实测数据见 §19.16.8 与 §19.20.4）：

| 字段 | 对称性 | 作用 | 实测灵敏度 |
|---|---|---|---|
| `掩体通过率` | 对称 | 双方命中率 | 主要拉长时间尺度；**兵力不对称时也会改变胜负** |
| `天气` | 对称 | 双方命中率，**逐场随机** | 雾 ×0.5 让回合数明显上升 |
| `无优势射程系数` | **非对称** | 一方的**射程** | 1.00→0.40 让成功率 31%→2% |
| `敌方输出修正` | **非对称** | 敌方的**输出** | 0.20→2.00 让成功率 100%→1% |

> `--sweep` 曾两次推翻"纵深"相关默认值（§19.21.4）：无条件后撤让结果单调变差，
> 直到把"**撤得出去**"写进判据为止。**一个字段若真的接进了模拟，扫描它就必须让结果单调变化；
> 若扫描结果纹丝不动，那它就是纯装饰。**

## 界面怎么用

| 区域 | 说明 |
|---|---|
| 预设对局 | 14 套现成编队。**前 4 套与控制台 `dotnet run -- demo` 同参数**，两边胜率应当一致 —— 这是"两个程序确实共用同一个计算核心"的交叉验证。另含空间机制专门预设（地形对比 / 近战混编 / 天气 / 远距离开局） |
| 我方 / 敌方 | 选模板 → 添加 / +5；选中一行后在下面逐项改数值，改动即时生效 |
| 单位字段 | 耐久、**近距命中率 / 远距命中率**、**射程(格)**、**移动(格/回合)**、射速/回合、伤害、破甲、护甲，以及**近战 / 地形优势**两个复选框 |
| 场景参数 | **初始距离(格)**、**近战射程**、**近端距离**、**无优势射程系数**、**移动策略**、**纵深上限 / 后撤速度系数 / 纵深策略**、掩体通过率、敌方输出修正、脱离接触折扣、倒地阈值、每回合 ticks、回合上限、撤退策略与阈值、双方目标选择策略、**天气** |
| 计算预告（200 次） | 蒙特卡洛 P50 / P90：成功率、撤退率、用时、伤员、阵亡、回合数、结局众数 |
| 跑 1000 场统计 | 结局分布 / 伤员分布 / 用时，并**校验预告 P90 包络**（实际超出比例应接近名义 10%） |
| 打一场 | 指定种子跑一次，看战报与逐人终局（含**终局纵深**）。战报包含空间阶段与甲弹对抗明细 |
| **战报日志过滤** | 顶部 6 个复选框：**开局 / 移动 / 攻击 / 受击 / 状态 / 结局** + 全选 / 全不选 / 默认。切换即刻重渲染，并显示 `共 N 条（攻击 x / 受击 y / 移动 z / 状态 w）` |
| 导出 / 导入快照 | 与控制台 `--dump` / `--replay` 互通：控制台 dump 出来的文本能粘进来复演 |

### 战斗日志（`DESIGN.md` §19.22）

| 类别 | 粒度 | 例子 |
|---|---|---|
| 开局 | 一次 | `开局：战线间距 40 格，天气 无（命中率 ×1），纵深上限 12 格。` |
| 移动 | 每单位每次位移 | `阿花 后撤 2.3 格 → 纵深 2.4（距敌前线 22.2）` · `战线间距 21.8 → 17.2 格` |
| 攻击 | 每次出手一行 | `Chisa → 海盗2 @19.4 格 · 命中率 34% · 射击 3 · 命中 1 · 甲弹对抗 弹开 0 / 减半 0 / 全额 1 · 合计 12 伤害` |
| 受击 | **每次命中一行** | `海盗2 受击（Chisa）· 甲 0.35 − 破甲 0.16 = 净 0.19 → 全额 · 本发 12 伤害 · 耐久 90 → 78/90` |
| 状态 | 变化时 | 倒地（含耐久比例与阈值）、阵亡、撤退触发、脱离接触 |
| 结局 | 一次 | 结局摘要 |

> **过滤发生在写入时**（预告的蒙特卡洛会关掉日志以省时间），所以"要看某一类"必须在
> 模拟之前选好 —— 控制台写法：`dotnet run -- battle outpost 4242 hit,status`。

### 空间模型速览（`DESIGN.md` §19.20）

```
开局 40 格（双方射程约 25 ⇒ 谁也打不着）
   ↓ 双方相互接近（已进射程的一方停下开火）
进入射程后交火，距离继续收缩到平衡点
   平衡点 = 全体参与单位中最短的有效射程
   例：带霰弹枪（有效射程 7.2）= 全队被拖到 7.2 格
```

- **地形优势**（默认开）⇒ 射程满额；**没有** ⇒ 射程 ×`无优势射程系数`（默认 0.75）。近战不吃这个惩罚。
  于是没有优势的一方要**顶着火力接近**。实测 1.00→31% / 0.75→8% / 0.40→2%。
- **近战**（长剑 / 野兽）射程恒为 1.5 格，会把交战距离一路拉近 —— 远程单位因此在冲锋途中能白打几轮。

## 它验证了什么、没验证什么

**验证了**（`--selftest` 30 项，全绿）：
- 护甲分布的**解析形式** == vanilla `ArmorUtility.ApplyArmor` 分支链（6 组 × 40 万次采样）
- 解析期望伤害 == 参照实现采样均值
- 同种子结果完全一致、不修改输入场景、随机性只经由注入的 `IRng`
- 护甲 / 火力单调性、撤退策略三档排序、Timeout / Victory 判定、撤退「脱离接触」轮
- **索敌同分随机**（`Random` 真的随机、`Strongest`/`Weakest` 不偏向名册顺序）
- **掩体通过率语义**（拉长战斗 / 镜像对局下中性 / 兵力不对称时会改变胜负）
- **空间模型**（开局够不着、地形优势抢到先手、近战拉近距离、移动关闭时停住）
- **天气**（逐场采样、差天气拉长战斗）
- 预告 P90 包络成立（**引擎自洽性**，非保真度）
- 快照编解码往返后结果一致

**没验证**（诚实边界，见 `DESIGN.md` §19.17.5 / §19.19 / §19.20.8）：
- 与**真实地图战斗**的一致性 —— 预告包络只是"同一引擎采样 vs 结算"的自洽检查
- 部位 / 疼痛 / 失血 —— 引擎用耐久池近似，倒地判定因此与 vanilla 有系统性偏差
- 视线 / 屋顶 / 烟雾 / 姿态 / 走位 / 射界 —— 无地图，全部取 1 或由上述旋钮统一补偿
- 贴脸命中率被高估（两点插值没有 vanilla 的 touch 段）
- 爆炸武器的溅射完全没建模（`GenExplosion` 需要地图）

模板里的数值是**标定用的占位值**，不是从真 pawn 读出来的。正式接入游戏后由
`CombatSnapshotFactory` 用 vanilla 的 `ShotReport.HitFactorFromShooter` /
`VerbProperties.GetHitChanceFactor` / `AdjustedFullCycleTime` / `ArmorUtility.GetPostArmorDamage`
折算真实数值，再喂给同一套核心。

## 结构

```
CombatLab/
  RimDelegation.CombatLab.csproj    net10.0-windows, WinForms
  Program.cs                    入口 + --smoke / --selftest / --render
  MainForm.cs                   主窗口（全部显式布局，便于离屏渲染核对）
  LabModel.cs                   模板 / 编队单位 / 场景参数 + SceneBuilder
  LabPresets.cs                 模板库与预设对局
  CombatLab.cmd                 启动器
  dist/                         已发布产物
```

计算核心**不在这个目录**，也不在 `Prototype/` —— 它已经搬进 **游戏 Mod 本体**，
三个工程链接同一批源文件：

```xml
<!-- CombatLab 与 Prototype 各自的 csproj -->
<Compile Include="..\Source\Combat\Core\*.cs" LinkBase="Core" />
```

```
Source/Combat/Core/      ← 计算核心（进 mod 的 DLL，同时被两个工具链接）
Source/Combat/Game/      ← 游戏侧适配层（RandRng / 快照工厂 / 威胁编队 / 评估对话框）
Prototype/Combat/Tests/  ← 离线自测（只有两个工具用）
```

即 **mod 跑的就是原型跑的那个核心**，不存在复制粘贴带来的漂移；
`--smoke` 会在同一个进程里把 CombatLab 预设与控制台 `Scenarios` 各跑一次比对胜率。
