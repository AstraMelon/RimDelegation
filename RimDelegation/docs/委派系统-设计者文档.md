## 0. 30 秒心智模型

**一句话**：委派系统把「世界地图上一个事件点上的作业」交给一支远行队，在**世界地图上**完成——不生成地图、不手动操作，按游戏内时间推进、按载重交付、按流程分段、按风险决策。

**三句话机制**：
1. **一个 `DelegationDef` 覆盖一类事件点**（按 `SitePartDef.tags` 或精确 Def 匹配）；玩法语义由 `DelegationWorker` 子类定义。
2. **状态挂在事件点上**（`WorldObjectComp_Delegations` 是唯一宿主），存量 `DelegationDeposit` **跨多次委派累计**。
3. **要有更多事件点时，优先只写 XML**：只有"玩法语义不同"才加 worker，只有"要新动作/新条件"才加原语。

**五条必须刻进脑子的不变量**：
| # | 不变量 | 一句话后果 |
|---|---|---|
| 1 | **收工/中止只有两个出口** `Complete` / `Abort` | 绕过它们 ⇒ 重复发信、重复记历史、重复排队报告 |
| 2 | **"算不算在干活"只有 `Delegation.IsWorkTime`** | 判据散开 ⇒ 出现"界面说在加班、休息条却在回升" |
| 3 | **存量挂事件点、跨委派累计** | 挂到委派上 ⇒「中止→重委派」刷新存量 = 刷资源 |
| 4 | **段表在开工时冻结** | 段表随状态变 ⇒ 存档里的下标指到别的段 |
| 5 | **文案与判据只有一份**（`DelegationUIUtility`） | 另一份 ⇒ 面板与信件/检视文本说两件事（RIM-3 后主控台只剩一种画法，"画法与数据说两件事"已不可能） |

**事件点"能不能被抽象"的三个问题**（不会回答就别动手）：
① 存量/规模从哪读（优先存档里的 `SitePartParams` 字段）？② 现场实物在哪（`SitePart.things` / 专用 comp）？③ **读不到怎么办**——`ForbidAbstract` 明确拒绝，还是按原版同一 maker 提前掷定并写回？
⚠️ **注意前提路径**：任务的"建点时清单已存在"只对**任务生成路径**成立；非任务生成的事件点要等生成地图时才掷。"读不到" ≠ "没有"，这两种来源都要兜住。

## 3. 契约与红线（动手前必读）

1. **不进图**：主线靠原版扩展点 `WorldObjectComp.GetCaravanGizmos` / `GetFloatMenuOptions` + `CaravanArrivalAction`。Harmony 白名单**恰好 4 个**（远行队检视文本 / 休息条 / 车队移动锁 / 野外伙食）——RIM-3 后主控台皮肤走**直接调用**，不再是第 5 个补丁点。**新增补丁要单独论证**。
2. **不为玩法在 `Delegation` 上加专用字段**：只用通用槽位 `resourceDef / rolledValue / totalCells / workerStage`（+ `workerAbortReason / extractionReport`）。⚠️ `rolledValue` 是复用字段（采矿=规模值、搜刮=已搬 kg）；**战斗种子已由 RIM-30 拆到独立字段 `combatSeed`**（它原本挤在 `rolledValue` 里，于是"清剿"既写种子又累加 kg ⇒ 进度行必然显示成「累计 532974 kg」）。一个 worker 同时要两种语义仍会互相覆盖。
3. **量纲由 worker 给**：`UnitName / WorkVerb / ActivityName / OutputUnitName / UntilDepletedLabel / StatusKeySuffix`。违反的典型症状：**搜刮点写出"委派开采中""采空为止"**。
4. **存档标签一律 `ro` 前缀**：原版把 `WorldObject` 上所有 comp 的字段**平铺在同一层 XML**（曾用 `active` 撞上别的 comp 的 bool 导致解析异常）。
5. **一次性动作必须落盘**：段进入钩子（交战会真打一场）靠 `flow.enteredPhase`；待搬清单（`lootBag` / `pendingCorpses`）搬完必须清空（否则读档可反复刷战利品）。
6. **异常必须兜住**：随机事件 `Apply`、估算、台账抄录、战斗结算都包 try/catch —— 一次事件/一次估算不该把游戏打崩。日志用 `Log.WarningOnce(..., 唯一码)` 防刷屏。
7. **静默失败必须喊出来**：Def 配漏、patch 没命中、组件没注册，都要在 `ModBoot` 自检或日志里出现。
8. **文案留在世界观内**：禁"生成地图 / 掷定 / GenStep / SitePart / 组件名 / Def"这类引擎词；值拿不到写「未知」，**不假 0、不让那一行消失**。
9. **画法与判据各只有一份**：主控台只有 Radius UI 一种画法（RIM-3 后"双端同一份"**作废**）；玩家可见的判据与公式仍只有一份，来自 `DelegationUIUtility` / `DelegationStageList`。
10. **面板只许有一个**：新增玩家可见区块前先问"能不能只是主控台的一个入口/一页"。

## 4. 操作指南 A：新增一种事件点

### A-0 先判断难度档

| 档 | 情况 | 要写什么 |
|---|---|---|
| **A-轻** | 玩法语义与现有 worker 同类（又是"按技能推进、产出直入车队"） | **零代码**：只加一条 `DelegationDef` XML |
| **A-中** | 语义不同，但能复用原语（进度按时间推、装车按载重） | 一个 `DelegationWorker` 子类 |
| **A-重** | 要新动作或新条件 | 再加一个 `DelegationEffectDef` / `DelegationConditionDef` 子类 |

     <workerClass>RimDelegation.DelegationWorker_TakeItemStash</workerClass> <!-- A-轻：复用现有 worker -->
     <targetSitePartTags><li>WorkSite</li></targetSitePartTags>
     <modes>…（抄现有 4 档）…</modes>
     <commandLabel>委派：{0}</commandLabel> …
     <!-- 可选：flowPhases / approaches / blockMapEntryAfterWorked / destroyTargetOnComplete / skillDef / 心情 -->
   </RimDelegation.DelegationDef>
   ```
4. **A-中/A-重才写代码**：`DelegationWorker` 子类（§5）或原语子类（§6）。
5. **要固定流程就加 `DelegationPhaseDef`**（§6 的字段表），再在 `flowPhases` 里引用。
6. **确认宿主已挂上**：`Site` 类 5 个 def 已由 patch 挂好；**新类型 `WorldObjectDef` 必须同时改** `Patches/RimDelegation_SiteComps.xml` 的 xpath **与** `ModBoot.SiteLikeWorldObjectDefs` 名单（两份手写清单，漏一处就"自检绿着但功能缺失"）。
7. **把这些静默失败点加进 `ModBoot` 自检**：清单门控指向不存在的段 / 等信号却没有揭露情报的段 / 收集段排在交战段之前 / 开了加班却没配心情。
8. **校验 XML**：`Check-DefsXml.ps1`（注释里两个连续减号 ⇒ 整份静默失效）。
9. **构建 → 部署**（§1.2）。
10. **看日志**：`DelegationDef N 个` 的 N 要 +1；清单行出现新 def 与**正确 tag**。
11. **验收五件**：就地入口 + 预先入口；有敌情 + 无威胁两岔（若配了条件段）；完成 + 中止两条出口；中途存读档各一次；量纲文案对（别写"采空为止"）。

## 5. 操作指南 B：写一个 `DelegationWorker` 子类

30 个虚方法**全部有默认实现，没有一个是必须覆写**。按"这个槽位不填会怎样"来决定覆写哪些：

| 组 | 方法（默认值） | 不覆写的后果 |
|---|---|---|
| **量纲文案** | `UnitName`("格") `WorkVerb`("采") `ActivityName`("开采") `OutputUnitName`("单位") `UntilDepletedLabel`("采空为止") `StatusKeySuffix`("Mining") | **UI 说假话**（搜刮写"开采中"、营救写"采空为止"） |
| **结构不变量** | `AllowsScaleIncrease`(false) | 若这门活规模是**现场实物**却返回 true ⇒ 事件放大后进度永远追不上总量 ⇒ 死循环 |
| **生命周期** | `OnStart` / `Tick(d,site,delta)` / `OnComplete` / `OnAbort`(空) | 什么都不发生 |
| **判据** | `WorkerAbortReason`(null) / `WorkerEndReason`(null) / `DepletedReason`(null) | 永不因本玩法收工/中止（只能靠通用结束条件） |
| **目标与台账** | `RollDeposit`(空) / `MakePreview` / `PreviewLabel` / `PreviewItems` / `ProgressItems`(null) | 没有"预期获得""还剩什么"，对话框与面板缺块 |
| **估算** | `EstimatedUnitsPerDay` / `EstimateUnitsPerDayFor`(0) / `EstimateUnavailableReason`(null) | 显示"无法估算"，且**原因会说错**（默认归因缺人/缺模式） |
| **交互** | `PawnDetail` / `GetGizmoIcon`(null) / `ProgressLabel` / `DeliverySummary` | 列表少细节、图标退回贴图路径、面板没有一行进度 |
| **姿态轴** | `ApproachForecast` / `ApproachFirstStrikePenalty`（已归一：直接转 `DelegationApproachDef.FirstStrikePenalty`） | 对话框没有成算；~~折扣与结算可能不同源~~ **RIM-27 已归一到唯一判据**（判据＝「确实在潜入」） |
| **交付** | `FlushDeliveries`(0) / `InspectWarning`(null) | 产出不交付；已知不精确之处玩家看不到 |

**两条实现惯例**：
- **`Tick` 里推进量必须对"本次可采量"封顶**（Mining 的 `added = min(cellsThisDelta, totalCells - cellsMined)`），否则会重复采集。
- 跨 tick 的小数预算**必须持久化**（搜刮的 `haulCarryOverKg`；理由：预算按 kg/小时算，而实物是离散的，不累积就只能"每 tick 至少搬一件"＝60 件/秒，速率失效）。

## 6. 操作指南 C：加一段流程 / 加一个原语

### C-1 加一段流程（**纯 XML，零 C#**）

`DelegationPhaseDef` 字段（`DelegationPhaseDef.cs`）：

| 字段 | 作用 | 易错点 |
|---|---|---|
| `hours` | 固定时长（1 小时 = 2500 ticks；≤0 会变成 1 tick 段⇒玩家看不见） | 前置段是**真耗时**，期间 `worker.Tick` 不跑，且计入 ETA / 计划天数 / 超时 |

## 9b. 操作指南 G：调满意度（RIM-5，**玩家与 modder 各一条路**）

**先认清一件事**：RIM-5 起作业模式**不再给效率、也不再直接挂心情** ——
模式只剩「作息窗口 + 作业强度」，**每天心情与作业速率都由满意度产出**（公式见 `DESIGN.md` §19.109）。

### G-1 玩家：Mod 设置页（本地配置，不进存档）

`设置 → 模组设置 → RimDelegation 边缘委派 → 满意度` 那一段：

| 想改什么 | 怎么改 |
|---|---|
| 整个机制关掉 | 取消「启用满意度」⇒ 满意度恒中性（每天心情 0、作业速率 ×1） |
| 某来源不算 | 取消那一行来源的勾选（四处都要开：总开关 + 该来源 + 该来源的 Def 默认 + 权重非 0） |
| 来源权重 | 那一行下面的「权重」按钮循环 0 → 0.5 → 1 → 1.5 → 2（**允许负数**：难度越高越有成就感就取负） |
| 效率/心情幅度 | 「效率幅度」「心情幅度」两颗按钮（档位表见同一页的公式说明） |
| 恢复初始 | 「恢复满意度默认值」⇒ 从 `Defs/RimDelegation_Satisfaction.xml` 重取 |

要**档位之外的浮点**（例如权重 0.37）：直接改
`Config\ModSettings\RimDelegationMod.xml` 里同名键，游戏内改一次设置即回写格式。

### G-2 modder：Defs（曲线、默认值、记忆文案）

| 想改什么 | 改哪里 |
|---|---|
| 曲线（吃喝窗口 / 远行宽限 / 强度跨度 / 默认幅度） | `Defs/RimDelegation_Satisfaction.xml` 的 `DelegationSatisfactionDef` |
| 四来源的**默认**开关与权重 | 同一个 Def 的 `sources` |
| 档位词与心情值（−8 / −4 / 0 / +4 / +8） | `RimDelegation_Thought_Satisfaction` 的 stages（档位数任意，`Stage()` 按比例分档） |
| 各模式的作业强度 | `Defs/RimDelegation_Delegations.xml` 的 `workIntensity`（+3 / 0 / −4 / −6） |
| 每顿吃的值多少 | `Defs/RimDelegation_FoodMood.xml`（野外伙食，4 阶段 −2 / 0 / +2 / +4；满意度直接读它的阶段值） |

**加一个来源**（例如"文化"）：在 `DelegationSatisfactionSource` 加枚举、`Compose` 里加一项子分、
`DelegationSatisfactionSourceEntry` 的开关/权重加进设置页即可 —— 公式是加权平均，加一项不用改别处。

### G-3 玩家在哪看满意度、悬浮情报怎么读（RIM-5 追加）

满意度**不再挂在模式行下面**，而是一条独立条目（用户原话：「把满意度单独拆成一栏，悬浮提供简要情报」）：

| 在哪看 | 长什么样 |
|---|---|
| 主控台右栏概览（在途 / 草稿 / 前往中） | 独立一行：主文字 `满意度 62%`、副文字 `干得挺顺 · 每天心情 +4 · 作业速率 ×1.036`（草稿/前往中标「（预计）」） |
| 草稿主列 | 模式行（可点换班）**下面**单独一行，不可点、但可悬浮 |
| 在途主列 | 「收集任务」段首一行（明细在概览栏那条的悬浮里） |
| 原版页签（皮肤不可用时的兜底） | 同一行里：`模式：常规作业 · 作业强度 0 · 满意度 62%（心情 +4/天 · 速率 ×1.036）` |

**悬浮情报**逐条摊开四个来源 + 一行汇总，例如：

```
· 最近一段时间的吃喝 67%（权重 1）：近 3 天 5 顿，平均 +2（−2 干粮 … +4 很好）

## 9c. 操作指南 H：调流程数值与旁白（RIM-11 ~ RIM-15）

> **一句话**：流程固定段的时长可以**全局缩放**、也可以给单个段加**随机偏移**；每一段/每一支委派的旁白由
> **四个池的并集**决定，每条旁白自己带一段可选的**行首方括号条件**。
> 需求条款见 `docs/委派系统-设计文档.md` **§R-2c**；完整设计记录（含用户原话与拍板编号）见 `DESIGN.md` **§19.111**；
> 机器复算与证据见 `docs/委派系统-现状审计与证据.md` **§16**。本节只讲"怎么调、怎么验、哪里会炸"。

### H-1 玩家怎么调（Mod 设置页；两项都是**本地配置、不进存档**）

| 想改什么 | 怎么改 | 生效范围 |
|---|---|---|
| 流程固定段整体快慢 | `设置 → 模组设置 → RimDelegation 边缘委派` 的「**流程固定段时长倍率**」⇒ 循环 `0.5× / 0.75× / 1× / 1.5× / 2×`（默认 `1×`） | **只对之后新开工的委派生效**：倍率在**开工那一刻冻结**，在途委派按开工时的值走到底（进度条不会跳变） |
| 流程里的随机旁白 | 「**流程显示随机描述（旁白）**」勾选框（**RIM-16 起默认开**） | 关掉 ⇒ 流程块没有任何旁白，而且**连掷定都不做**（与 RIM-13 之前逐字一致） |

### H-2 modder 怎么调（全部在 XML；改完必看 H-4）

| 想调 | 字段 | 说明 |
|---|---|---|
| 一段固定流程的时长 | `DelegationPhaseDef.hours` | 1 小时 = 2500 ticks；`≤0` 会变成 1 tick 段（玩家看不见）。前置段是**真耗时** ⇒ 计入 ETA / 计划天数 / 超时 |
| 一段的随机偏移 | `DelegationPhaseDef.hoursJitter` | 单位小时；**空 / `0` = 不抖**。写 `0.5` ⇒ 这一段落在 `base ± 0.5h`。**只该配给收尾段**（理由见 H-5 ③） |
| 段内换旁白间隔 | `DelegationPhaseDef.ambientRerollHours` | **字符串**：`"0.5"` = 固定间隔；`"0.5~1.5"` = 每次抽完重掷下次间隔。本文件 18 段**已统一配 `0.5~1.5`** |
| 主作业段的换句间隔 | `DelegationDef.workAmbientRerollHours` | 同上（主作业段的旁白不归 `DelegationPhaseDef` 管） |
| 某一类情境的旁白 | `DelegationPhaseDef`：`ambientLines` / `ambientLinesSolo` / `ambientLinesPacked` / `ambientLinesHostile`；`DelegationDef`：同名 `workAmbientLines*` + `restAmbientLines` | **四个池是并集、不是优先级**（RIM-13 改的）：池名只提供**隐式标签** —— `ambientLinesSolo` → `solo`、`…Packed` → `packed`、`…Hostile` → `hostile`、默认池无标签 |
| 单条旁白的出现条件 | **行首方括号指令** | 见下表；不写指令 = 永远可说 |

**行首指令语法**（唯一一份实现在 `Source\AmbientLine.cs` 的类注释；全部可选，用 `|` 分隔，标签之间也可以用逗号）：

| 指令 | 含义 |
|---|---|
| `solo` / `group` | 只有 1 个人 / 多人时才说 |
| `packed` / `hostile` | 队伍带驮兽 / 该地点真有守军时才说 |
| `night` / `day` | 当地时间 20:00–06:00 / 06:00–20:00 |
| `early` / `mid` / `late` | 本段进度 `<34%` / `34–80%` / `>80%` |
| `w=N` | 权重（默认 1）；抽中概率 ∝ `weight × (1 + 标签数)` |
| `p=A-B` | 进度百分比区间（可只写一头：`p=80-`） |
| `h=A-B` | 当地小时区间（**跨零点照写**：`h=22-5` = 22 点后或 5 点前） |
| `t=TraitDef:degree` | **队伍里有人**带这个特质（分度特质**必须写 degree**） |
| `ts=TraitDef:degree` | **这一段的说话人本人**带这个特质 |
| `c=GameConditionDef` | 存在这个全球事件（`Find.World.GameConditionManager`） |
| `once` | 每支委派只说一次 |

例：`<li>[night,late|w=2] 天快亮了，火也快灭了。</li>`
**不写指令 = 永远可说**：旧的 `<li>纯文本</li>` 照样有效，260 条老旁白一条都不用改写。

### H-3 加一条旁白 / 加一个池：最小步骤

1. **加一条旁白**：在目标段（或目标委派的 `workAmbientLines*` / `restAmbientLines`）的对应池里加一行 `<li>…</li>`；要条件就在行首写 `[…]`。
2. **加一个"池"**：池的种类是**固定四类**（默认 / 单人 / 驮兽 / 敌情）——**"第九类池"未实装**。想要新的情境分类，正确做法是加一个**新的行首标签**（要动 C# 的 `AmbientLineSyntax` / `Matches`），而不是加新字段。
3. **跑体检**：`tools\Check-DefsXml.ps1`（见 H-4）。它会打出该段四个池各多少条，并 WARN 条数 `< 3` 的池。
4. **进游戏看**：启动横幅的 `DelegationPhaseDef 18 个` 不变（只加旁白不加段）；出现新的 `[RimDelegation]` Warning 就查 H-5。

### H-4 改完必跑

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Game\Rimworld Dev\RimDelegation\tools\Check-DefsXml.ps1" "D:\Game\Rimworld Dev\RimDelegation"
```

**退出码语义**（照脚本头部注释）：

| 退出码 | 含义 | 该怎么做 |
|---|---|---|
| `0` | 良构且**零 WARN** | 可以部署 |
| `1` | 有 XML **不良构**（多半是注释里两个连续减号） | **不要部署**；按脚本点名的文件与行号修 |
| `2` | 良构、但有**流程数值 WARN**（时长与注释对不上、某池条数不足…） | 可以先部署，但先把清单看完 |

脚本做 **5 件事**（RIM-11 扩写）：① 良构性扫描根＝**Defs + Patches + Languages**；② 18 段流程表（时长 / 抖动 / 前后置 / 条件 / 位置 / 技能 / 四池条数）；③ 各委派固定流程合计，并**与注释里手写的数字对账**；④ 随机事件期望频率复算并与注释对账；⑤ 从 `Source\*.cs` 现取 public 字段名做 **Def 字段名白名单**。

**还要看启动横幅**：`ModBoot.CheckFlowNumbers()` 会喊两条 —— ① 同名段 `hours` 不一致；② 某段所有池加起来 `≤1` 条（会永远念同一句）。这是 `ModBoot` 里**第一条查"数值对不对"而不是"东西在不在"的检查**，有 Warning 就是数值没配好。

### H-5 陷阱

1. **`<li>` 与注释里绝不能出现连续两个减号** ⇒ 整份 XML 静默失效（S26 真事故）。RIM-11 起体检脚本的扫描根已扩到 `Languages\`（当年英文 Keyed 的 `--` 就是被"只扫 Defs"漏掉的）。
2. **行首指令写错 ⇒ 那一条永远不出现**：解析失败会把原文记进 `syntaxError`，进游戏后由 `ConfigErrors` 点名。
3. **`hoursJitter` 只该配给收尾段**（`afterWork = true`）：前置段抖动会让"开工那一刻给出的预计完工时刻"当场变成谎话。
4. **池 `< 3` 条会明显重复**（脚本会 WARN；`ModBoot` 那条更狠：四池加起来 `≤1` 条）。
5. **Def 字段名写错不会让 XML 不良构**，只会在 `Player.log` 里被静默忽略（症状是"改了没效果"）—— 脚本第 ⑤ 项专抓这个。

## 10. 已知陷阱清单（都踩过）

1. **XML 注释里两个连续减号** ⇒ 整份 Def 静默失效、游戏不崩不报（S26 真事故：委派功能整体消失）⇒ 改完必跑 `Check-DefsXml.ps1`。⚠️ **RIM-11 起该脚本的扫描根已从 `Defs\` 扩到 `Defs + Patches + Languages`**（当年英文 Keyed 的 `--` 就是被"只扫 Defs"漏掉的）—— 那两处不必再自己盯了。

3. **`ro` 前缀**：WorldObject 上所有 comp 字段平铺同一层 XML，撞名即解析异常。

2. `MainButtonWorker.DoButton` 的 `Disabled` 早退在**画图标之前** ⇒ 置灰不画图标（角标要自己画）。
3. `EnterCooldownComp`：`Start(Nullable<float>)`/`Stop()`/`BlocksEntering`/`DaysLeft`/`TicksLeft`；原版 `PostMapGenerate` 会自己 `Stop()` ⇒ 进行中封锁要短窗口续期。
4. `QuestPart_WorldObjectTimeout → QuestPart_Delay → QuestPartActivable`，后者有 private 字段 `state`（恢复 30 天计时的反射目标）。
5. 世界地图右键菜单只在一支车队被**唯一**选中时存在 ⇒ 右键事件点的委派菜单天然带车队语境。
6. 世界地图侧**没有实时天气**（`WorldWeather` 0 命中、`WeatherManager` 只挂 `Map`）。
7. **RIM-14 补核（本机 RimWorld 1.6.4871 / `Assembly-CSharp` 1.6.9676.17735）**：
   `RimWorld.GenLocalDate.HourOfDay` 有 **3 个重载** `(Map)` / `(Thing)` / `(PlanetTile)`，都返回 `int`，
   **没有** `HourOfDayFloat`（浮点版叫 `HourFloat`）⇒ 世界地图侧取"当地小时"要走 `(PlanetTile)` 那个重载。
8. `RimWorld.TraitSet.HasTrait` 有 **2 个重载**：`(TraitDef)` / `(TraitDef, int degree)`；`Trait.Degree` 是**只读 `int`**。
   单参重载**只比 def、不比 degree** ⇒ 分度特质（如 `NaturalMood` 的 2 / 1 / −1 / −2）**必须写 degree**。
9. `RimWorld.GameConditionManager.ConditionIsActive(GameConditionDef)` **只有 1 个重载**；`Find.World` → `RimWorld.Planet.World` 有 `GameConditionManager` 属性 ⇒ 世界级全球事件判据可用。
10. **天气层做不到（实证）**：42 个含 `Weather` 的类型里，`WeatherManager` 的唯一宿主是 `Verse.Map.weatherManager`
    （`Planet.Tile` / `Site` 没有任何天气成员，`WorldWeather` 在整个 `Managed` 目录 **0 命中**）
    ⇒ "正在下雨 / 雷暴"在世界地图上无数据源。替代路径＝**世界级 `GameCondition` → `GameConditionDef.weatherDef` → 某地图天气**。
    详见 `docs/委派系统-现状审计与证据.md` §16.6。
> ⚠️ **取证方法学坑**：**Windows PowerShell 5.1（.NET Framework 4.8）加载不了 1.6 的 `Assembly-CSharp`** ——
> 27 个类型因默认接口方法（DIM）抛 `TypeLoadException`，而 `GetType()` 会**静默返回 `null`**，极易被误判成"API 不存在"。
> 反编译取证必须用 **.NET 5+ 宿主**（本项目的 `DecompilerServer` 就是）。
