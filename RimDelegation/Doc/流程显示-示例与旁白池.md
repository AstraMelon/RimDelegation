两件必须先说清的事，否则示例会被误读：

1. **阶段3 是"主作业"**：它不在 `flowPhases` 里。前置 3 段走完之前 `DelegationWorker.Tick` **完全不跑**；走完之后才是"搬运"，而它的进度是**件数**、不是固定小时。要让它像其他阶段那样出现在同一条列表里，得先把"固定段 + 主作业 + 收尾段"合成一个统一阶段序列（见 §5.4）。
2. **"Chisa 已完成"里的人名是叙事主语，不是"只有他在干活"**：前置段是**全队一起走**的（那段时间 worker 完全不跑，代码里没有"谁在执行这一段"的概念）。所以人名只能从参与者里**随机挑一个当代表/说话人**。除非你想给阶段加真正的"执行者"语义 —— 那需要给每段指定角色（侦察=射击最高者、破门=采矿/建造最高者…），这是另一件事，要你点头我才做。

## 5. 可实施性核对（动手前要解决的 6 件）

### 5.1 字形：你草图里的 ✅🔵↳ 建议全换掉 `[验证]`

游戏目录里**没有独立字体文件**（我扫过全盘 `*.ttf/*.otf`），`Verse.Text` 用的字面量是 `Fonts/Arial_small` / `Fonts/Arial_medium`（Unity 内建资源）。`resources.assets` 里能挖出 3 个嵌字体，我解析了它们的 cmap（脚本见 `tools/Check-RimWorldFonts.js`，可重跑）：

- **有**：`×` `·` `—` `…` `→` `←` `●` `○` `└` `█` `░`
- **缺**：`✓`(U+2713) `✔` `★` `▶` `◆` `↳`(U+21B3) `⚠`(U+26A0) `⚡`(U+26A1)，以及**全部 emoji**（✅ U+2705 / 🔵 U+1F535 / ⏳ U+23F3）

⚠️ 但有一个反转：原版 C# 字符串里 `✓` 有 11 处先例（**全在 `DebugOutputs*` 开发工具里**），而上面这 3 个嵌字体都缺 `✓` —— 所以"✓ 到底能不能显示"我**没能证实**（可能 UI 走的是别的字体，也可能 dev 工具的方框一直没人管）。

👉 **顺手请你看一眼**：现在游戏里①参与者行左侧的 `✓`、②检视面板那句 `⚠ 存量由委派按 GenStep…` 显示正常吗？如果这两处是方框/空白，那现在用 `✓`/`⚠` 的地方也得一起换掉。

**[建议] 不赌字形的落地写法**：
- 完成标记 → 自绘（`Widgets.DrawBoxSolid` 画小方块/贴图）或直接用上面"有"的字符：完成 `·`（配绿）、进行中 `●`（配强调色）；
- 旁白前缀 → 不用 `↳`，改成**缩进**（前导 2 个全角空格）；
- 人名上色 → `[反编译]` `Verse.Pawn.NameShortColored` 存在，直接用。

### 5.2 进度条：就用**同页面已有的那两条**（按你的要求）

- **原版侧**（`Window_Delegations` 列表行/详情区、`WITab_Caravan_Delegation`）：`Widgets.FillableBar(rect, frac)` —— 8px 高、无内嵌文字，百分比写在旁边。阶段条沿用同一 API、同样 8px。
- **皮肤侧**（`CaravanTabSkin.DrawProgressRow`、`DelegationConsoleSkin`）：`UIKit.Flat.Bar(rect, frac, label)` —— 16px 高、**百分比在条内**。阶段条沿用它。
- ⚠️ 已知坑（之前测到过）：`UIKit.Flat.Bar` 在 frac 很小时会把条**强制拉到"标签宽 + 14px"**（6.4% 会画成一个约 40px 的小方块）。阶段刚开始（0%）最明显 ⇒ **二选一**：① 皮肤阶段条仍用 `UIKit.Flat.Bar`，但标签只写百分比，"0.3h/1h"挪到行尾；② 皮肤阶段条改用原版 `FillableBar` 那一套画法（与"总进度"那条不同，但更像进度条）。

### 5.3 随机必须"掷定一次"（否则画面会闪）

旁白/说话人如果在 `OnGUI` 里当场随机，**每帧都会变**。要存进 `DelegationFlowState`：

```csharp
public int stageSpeakerIndex;   // 当前段的说话人（participants 下标）
public int stageVariantIndex;   // 当前段选中的旁白编号
public int stageStartTick;      // 进入该段的时刻（用来算"耗时"）
```

另外"耗时 XXh"要显示**实测值**的话，还得记住每段的完成时刻（`List<int> phaseDoneTicks`）—— 现在的 `DelegationFlowState` 只有 4 个标量。
（固定段的"耗时"其实就等于 `DelegationPhaseDef.hours`，因为推进是"每 tick 累加 delta"；要显示真·墙钟时间才需要额外记账。）

### 5.4 结构改动（最大的一块）

现在 `DelegationFlow.Lines()` 把前置 3 段 + 收尾 1 段**全列**出来（未开始的也列 1 行）。你要的是"已完成累积 + 当前三行块"，中间还要插入主作业段。落点建议：

- 新增公开件 `DelegationStageList.Build(d, site)`：返回有序阶段列表，每项含 `state(未开始/进行中/完成)` / `title` / `progress01` / `etaHours` / `speaker` / `ambient`；
- 原版页签、主控台详情、RadiusUI 皮肤三处都只调它（沿用你们"文案与画法只有一份"的准则）；
- 采矿/营救**没有 `flowPhases`** ⇒ 它们的阶段序列只有"主作业"一项（要不要显示见 §6 第 1 问）。

### 5.5 高度要重算

页签的 `BottomReserve(width, flowLines, …)` 是按**行数**算的（S8 的纯函数，`CaravanTabSkin` 有镜像）。一个阶段从 1 行变成 3 行（标题 + 旁白 + 条），5 段就是 15 行 —— 页签一定放不下，必须配 §3 的折叠规则，两个副本一起改。

### 5.6 文案归属

旁白池建议放 Def（`DelegationPhaseDef.ambientLines` + `doneLines`）：可翻译（DefInjected）、可热重载（改词不用重编译）、新增阶段只写 XML —— 与"加 def 不加代码"的目标一致。代价是 XML 里会有一堆句子。
（备选：继续 .cs 硬编码，与现在 Keyed 的用法一致。）
