## 1. 宽度账 `[源码]`（这是"能不能拆一栏"的全部依据）

- 窗口内容宽 `C = winW − 36`（`Verse.Window.Margin = 18`，`[反编译] Verse.Window.Margin`）再 `− 24`（皮肤 `Pad = 12`）⇒ **C = winW − 60**。
- 左栏 `min(340, C×0.30)`、右栏 `min(320, C×0.28)`、栏间共 2px（`DelegationConsoleSkin.cs:180-184`）。

| 窗口宽 | C | 左栏 | 右栏 | 主列（现状） | 切 300 给流程栏后 | 结论 |
|---|---|---|---|---|---|---|
| 1180（现默认） | 1120 | 336 | 313.6 | **468.4** | **168** | ❌ 主列崩 |
| 1300 | 1240 | 340 | 320 | 578 | 278 | ⚠️ 流程栏最多 ~138 |
| 1400 | 1340 | 340 | 320 | 678 | 378 | ⚠️ 流程栏最多 ~238 |
| **1490** | 1430 | 340 | **300** | **468** | — | ✅ **提案尺寸** |

- 屏幕上限 `UI.screenWidth − 16`（`[源码] Window_Delegations.cs:129`），而 `UI.screenWidth = Screen.width / Prefs.UIScale`（`[反编译] Verse.UI.ApplyUIScale`）
  ⇒ 1920@1.0 ✅ / 1920@1.25 = 1536 ✅（余量 30px）/ **1920@1.5 = 1280 ❌**。
- **退化规则（`[推导]`）**：`flowW = clamp(C − 340 − 320 − 2 − 440, 0, 300)`；`flowW < 200`（即 `winW < 1362`）时**整栏折叠**，流程回到主列 ⇒ 永不出现"挤到读不出来"的栏。
- ⚠️ 老存档已存 `winW/winH`（`RimDelegationSettings`）⇒ 改默认值对老玩家**无效**，要走 `geomVersion` 提升作废旧几何（`RimDelegationSettings.cs:86` 已有这个开关）。

## 2. 流程栏排布（草案）

示例时刻：**有敌情那条流程、已完成 4 段**（这个时刻正好同时演示"压行规则"且数字自洽：1h + 0h + 1h + 1h = 3.0h）。

```
流程                                已走 4/7 段 · 已用 3.0h
│
├ · 战术侦察 · 战斗评估 · 交战 · 搜集战利品（已完成 4 段，共 3.0h）  ← 已完成 > 3 段：压一行
├ ● 全队 正在建立营地（0.2h / 0.5h）                                ← 当前段三行
│   「把帐篷支在背风的那一侧，没人想再挪第二次。」
│   [=== 条 ===]              预计还需 0.3h
└ （未开始的「开采 / 撤离」一个字都不画 —— S14 拍板"完全隐藏"）
```

同一条规则用在**无威胁**那条（4 段）上，就是"已完成 1 段逐行 + 当前段三行"：`已走 1/4 段 · 已用 1.2h`（环境侦察 1h + 建立营地已走 0.2h）。

- 条：**复用同页面那条** `UIKit.Flat.Bar`（`Cursor.Progress` 内部就是它），不新造。
- 连线/节点：`CardChrome.Fill` 画 1px + `CardChrome.Rounded` 画小点（`[推导]`：原版与 RadiusUI **都没有** Splitter/分隔条控件，拖拽分隔条要自绘 ⇒ 本版先固定宽度）。
- 字形红线：`✓ ✔ ✅ 🔵 ⏳` 与全部 emoji **画不出来**（本项目已踩过）⇒ 完成 `·`＋绿、当前 `●`＋强调色、旁白用**缩进**代替 `↳`。
- 已完成段 > 3：压一行汇总 + 完整清单进 tooltip（`DelegationStageList.Rows(maxDoneRows)` 现成）。
- 流程栏自己可滚动（内容总高由 `Cursor` 空跑一趟算出 + 显式 viewRect，与主列同款，不靠 Layout 趟测高）。

## 3. 采矿的两岔流程（本次样板）

| 段 | 类型 | 基准小时 | 技能 | 执行者 | 条件 |
|---|---|---|---|---|---|
| 环境侦察 | 前置 | 1h | 射击 | 单人（技能最高） | 无威胁时走这条 |
| 战术侦察 | 前置 | 1h | 射击 | 单人（技能最高） | **有敌情时**替换环境侦察 |
| 战斗评估 | 前置 | 1h | 智识 | 单人 / **玩家可瞬间完成** | 有敌情 |
| 交战 | 前置 | 1h（**叙事耗时**） | **不挂钩**（走真实战斗模型） | 全员 | 有敌情 |
| 搜集战利品 | 前置 | 1h | 战斗 max + 智识（§4.1） | 单人（技能最高） | **数据源留白** |
| 建立营地 | 前置 | 0.5h | 建造 | 全员 | 两岔都有 |
| 〔主作业〕开采 | 主作业 | — | 采矿 `[源码]` `SkillDefOf.Mining` | 全员 | — |
| 撤离 | 收尾 | 2h | 无技能（按人数 + 负重整体算） | 全员 | — |

- **「交战」为什么也占 1h**：模拟战斗本身是**一次性结算**（进入该段的那一 tick 就跑完 `CombatSimulator.Simulate`，种子存 `d.rolledValue`，与营救同款），所以它的 1h 是**叙事耗时**（交火、清点、包扎那段时间），不是"战斗模型跑 1 小时"。不这么定的话这一段会在同一 tick 里闪过，流程栏上根本看不到。
- **无威胁**：环境侦察 → 建立营地 → 开采 → 撤离，固定工时合计 **3.5h**。
- **有敌情**：战术侦察 → 战斗评估 → 交战 → 搜集战利品 → 建立营地 → 开采 → 撤离，固定工时合计 **6.5h**（评估由殖民者做；玩家瞬间完成评估则 **5.5h**）。
- ⚠️ **加流程 = 加时间**：前置段期间 `worker.Tick` 完全不跑（`[源码] WorldObjectComp_Delegations.cs:1043`），并经 `Delegation.FlowRemainingTicks()` 计入 ETA / 计划天数 / 超时 ⇒ 上面的数字直接推后整单工程。
- ⚠️ `hours = 0` 的段**看不见**：`Ticks` 最小 1 + `AdvancePrelude` 是 while 循环 ⇒ 连续 0 小时段在同一 tick 内连过（`[源码] DelegationFlow.cs:145`）。所以"只叙事不耗时"必须另设开关，不能靠 0。

## 4. 技能挂钩（全段）

### 4.1 搜集战利品的权重设计（用户要求"权重你帮忙设计"）

**用户原话**：「格斗/射击取最高的（战斗经验丰富），智识，提供一定增益」。

```
有效等级 = round( 0.7 × max(射击, 格斗) + 0.3 × 智识 )      // clamp 0..20
skillFactor = 0.6 + 0.04 × 有效等级                          // 现成尺子
段实际耗时 = 基准小时 ÷ skillFactor
```

| 小人 | 有效等级 | skillFactor | 1h 段实际耗时 |
|---|---|---|---|
| 射击 20 / 智识 0 | 14 | 1.16 | 0.86h |
| 射击 12 / 格斗 6 / 智识 8 | 11 | 1.04 | 0.96h |
| 射击 10 / 格斗 10 / 智识 10 | 10 | 1.00 | 1.00h |
| 射击 0 / 智识 20 | 6 | 0.84 | 1.19h |
| 全 0 | 0 | 0.60 | 1.67h |

- **为什么 7:3**：战斗经验是主导（原话"战斗经验丰富"），智识是增益（原话"提供一定增益"）；7:3 让"战斗 20 / 智识 0"（14 级）略低于"双 10"（10 级）之上但又够不到满级，避免纯战斗号一家独大。
- **为什么 `max` 而不是平均**：原话是"取最高的" ⇒ `max(射击, 格斗)`，且天然把"只会打枪"和"只会抡刀"的人平等对待。
- **备选**（要更偏智识就换）：`0.6/0.4`；或 `max(战斗, 智识)` 不混合。
- **XP 建议**：按同一权重**分给两个技能**（0.7 给主导战斗技能、0.3 给智识）；备选 = 只给主导技能。⚠️ 待拍。

### 4.2 全表

| 段 | ★推荐 | 备选 | 依据 / 风险 |
|---|---|---|---|
| 环境侦察 / 战术侦察 | **射击** | 智识、驯兽 | 侦察＝看地形、数岗哨、记换岗规律；原版 Hunting 亦用 Shooting |
| 战斗评估 | **智识** | 射击 | 原版研究/破解/分析实体都是 Intellectual；评估本质是分析 |
| 交战 | **不挂钩** | — | 战斗结算本来就读参与者真实射击/格斗/装备（`CombatSceneFactory`）⇒ 别再加一层 |
| 搜集战利品 | **战斗 max + 智识（7:3）** | 建造（撬箱/拆件） | §4.1；原版**没有**"打扫战场"这项工作，属本项目新造 |
| 建立营地 | **建造** | 种植 | 搭营地＝建造，与原版 Construction 同源 |
| 〔主作业〕开采 | 采矿（现状） | — | `[源码]` `DelegationWorker_Mining.cs:409` |
| 撤离 | **无技能**（人数＋负重整体算） | 射击（且战且退） | 撤离没有技术含量，按整体算更合理 |

**现成的尺子（必须复用，别造第二套）`[源码]`**：
- `DelegationDef.skillDef`（单技能）—— 已用于参与者排序、采矿速率、XP；
- `DelegationApproachDef.skillDefs`（列表）+ `RescueUtility.BestSkillLevel(pawns, skillDefs)`；
- `RescueUtility.PercentPerWorkHour(pawnCount, bestSkill, mode)`：`skillFactor = 0.6 + 0.04×clamp(level,0,20)`（0 级 0.6 → 10 级 1.0 → 20 级 1.4），`× 人数 × mode.workRateMultiplier`；
- XP：采矿 `XpPerTick = 0.07`、搜刮 `0.035`，写法 `p.skills.Learn(skill, 系数 × delta × 倍率)`。

## 5. 「超凡智能」= **玩家本人**（不进 Def）

用户澄清：「超凡智能指代Player，不存在于Def里面」。范围：**只评估**。

```
● Chisa 正在评估守军 …（0.4h / 1h）      ← 锻炼殖民者：按技能耗时 + 给 XP
  或
● 超凡智能已完成评估（0.0h）              ← 玩家本人：瞬间、耗时 0、不给 XP
```

- 机制：评估段多一个 `Player` 执行分支 ⇒ 该段直接标 Done（耗时 0h）、旁白改写一句、`ticksWorked` 不涨。
- 实现接口：`DelegationPhaseDef.playerMayDoInstantly`（bool，默认 false）。
- ⚠️ **红线**：瞬间完成**必须 0 XP**，否则就是"拿时间换技能点"的机器。此条建议写进 rules。
- 数值感受（便于定 XP 系数）：评估 1h、1 人、10 级 ⇒ `0.07 × 2500 × 1 ≈ 175 XP`；原版升到 10 级要数万 XP ⇒ 单段不会变成刷技能机。

## 6. 自动选人 + 预留接口

- `DelegationPhaseDef.speakerMode` 现只有 `RandomPawn / All / None` ⇒ **新增 `BestSkill` 档**：选该段技能最高者，并列时沿用现有哈希（不跳人）。
- 现有的"说话人"（`DelegationAmbient.SpeakerName`）只是**叙事主语**；本次把它升级成**真·执行者**：段速率读这个人的技能，UI 上的名字就是真的执行者。
- 多人段（`All`）按**整体**算 = `人数 × 队伍最高技能`（现成口径）。
- **预留接口**（第一版不接 UI）：`DelegationPhaseDef.executorOverride`（或 comp 上的一张 `phaseKey → pawnID` 表），将来做"我指定侦察让 Chisa 去"时直接读它。
